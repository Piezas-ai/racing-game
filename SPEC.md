# Vancouver Road Simulator — 2-Player Online Racing Game

*by Jasper, Skyler, Dad and Fable*

## Summary

A Mario Kart-style racing game for up to 10 players racing each other over the
internet — plus up to 20 AI robot racers the host can add. Players register with
username + password, join a race by 5-digit code, and race 3 laps on a
procedurally generated track. Lucky blocks give random items (including a jump
scare you can fire at your opponent), and tracks are littered with spikes and
snapping traps. Maps are generated by difficulty level (1 = giant circle →
5 = twisty gauntlet) and themed by biome (jungle, snow, desert, volcano). Pets
bought in the shop ride along and grant passive abilities.

## Stack & Deployment Mode

- Deployment mode: `next-bff` per `piezas.manifest.json` — read as "frontend with a
  small server layer". Real-time racing needs a long-lived WebSocket server, so the
  server layer is a small Node process (Express + `ws`), and the frontend is
  Vite + React rendering the game on a `<canvas>`.
- Dev: Vite on :5173 proxies `/api` and `/ws` to the game server on :8787.
- Prod: the same Node server serves the built client from `client/dist`.

## Piezas Ownership Mapping

| Need | Owner | How |
|---|---|---|
| Accounts, credentials, sessions | Piezas Users service | per-app policy (`appId` = deploy slug), password sign-in, ES256 session tokens |
| Player game data (stats, wallet, garage, pets) | Piezas Entity Records | `player` entity (references the users-service account via `userId`) |
| Race results/history | Piezas Entity Records | `race` entity |
| Leaderboard | Piezas Entity Records | list `player` sorted by wins |
| App login/session glue | App | username→synthetic-email mapping + httpOnly cookie carrying the platform session token |
| Real-time race state (positions, items, countdown) | App (workflow orchestration) | in-memory rooms + WebSocket relay; ephemeral, never persisted locally |
| Secrets | Server-only env | `PIEZAS_API_KEY` |

No local database. Durable data lives only in Piezas; the app stores Piezas record
IDs in session/room state.

### Entities (defined idempotently at server boot)

- `player`: username (text, required), userId (text, users-service account ref),
  wins (integer), losses (integer), races (integer), bestLapMs (integer),
  wallet fields, color/car (text), pets (longtext JSON array), activePet (text).
  No credentials — those live in the users service.
- `race`: level (integer), biome (text), seed (integer), playerAId/playerBId (text),
  playerAName/playerBName (text), winnerId (text), winnerName (text),
  durationAMs/durationBMs (integer), status (select: completed | forfeit),
  finishedAt (datetime)

## Auth

Credentials and sessions are owned by the Piezas Users service (the platform's
managed end-user identity component). The app keeps its username-only UX — the
users service is email-keyed, so usernames map to deterministic non-routable
emails (`username@racers.local`) and the real username + player record id ride
in the account profile.

- Policy (idempotent upsert at boot, `appId` = `racing-game-7725`): password
  method, 7-day sessions, min length 6, no email verification, MFA off
  (synthetic emails can't receive codes).
- Register: username 3–16 chars `[a-zA-Z0-9_]`, password ≥ 6 chars. Player
  record created first (its id goes into the account profile), then
  `users.signUp` + `users.signIn`. Duplicate sign-ups return a decoy user
  (anti-enumeration), so the sign-in is the proof of ownership; on failure the
  record is rolled back and the username reported taken.
- Login: `users.signIn`. Accounts from before the migration are lazily
  migrated: legacy scrypt hash on the player record is verified once, the
  account imported with the plaintext in hand (`users.importUsers` — the
  service re-hashes), and the old hash drained from entity data (PZ-69).
- Session: the httpOnly cookie carries the platform's ES256 session token.
  Every request (and the WebSocket upgrade) verifies via `users.getSession`
  behind a 60-second in-memory cache; sliding-refreshed tokens re-set the
  cookie. Logout revokes platform-side via `users.signOut`. `SESSION_SECRET`
  is gone.

## Game Codes & Race Flow

No matchmaking queue. One player creates a game and shares a short numeric code —
easy to say out loud. The join URL is `/game/<code>` (e.g. `/game/12345`).

1. Authenticated host connects to `/ws` and sends `create { level, biome }`; the
   server allocates a random unused 5-digit code and replies `created { code }`.
   The client shows a staging room with the shareable URL and switches its address
   bar to `/game/<code>`. Waiting rooms expire after 30 minutes.
2. Up to 9 more players open `/game/<code>` (or type the code in the lobby); each
   `join` broadcasts a `lobby_update` roster (including the robot count/skill)
   to everyone in the staging room. The host can dial in 0–20 AI robots.
   Joining your own code from other tabs/accounts is allowed (handy for testing).
3. The host sends `start` (slot 0 only). The server loads everyone's wallet and
   sends each player `race_config { raceId, code, seed, level, biome, players[],
   yourSlot, loadout }`. All in-race relays are slot-tagged `peer_*` messages
   fanned out to every other racer. Jump scare and lightning hit ALL other racers.
4. All clients deterministically generate the identical track from the seed and
   send `ready`; the server runs a 3-2-1-GO countdown. Each client simulates its
   own kart at ~20 Hz state broadcast; hits on a kart are decided by that kart's
   own client (victim-authoritative) and reported for scoring. No anti-cheat —
   documented non-goal.
5. Placements: finishers by time, then still-connected non-finishers, then leavers
   (DNF, 0 points). Winner = first finisher; stragglers get 60 s after the first
   finish. `race_over` carries full standings; results + stats persist to Piezas.

## Track Generation (deterministic, shared code)

`generateTrack(seed, level, biome)` — same module runs on both clients.

- Centerline: 12–20 control points around a circle with radial noise; amplitude
  and harmonic count scale with level (level 1 = amplitude 0 → perfect circle).
  Catmull-Rom smoothing to ~700 points; loop closed.
- Track width: 120 px at level 1 down to 78 px at level 5.
- Hazards placed at seeded centerline offsets: spikes `2 + 2×level`, snapping
  traps `2×level − 1` (open/close on a seeded phase; hitting a closed one =
  spin-out).
- Lucky block rows: 4 + level blocks; respawn 5 s after pickup.
- Biomes: palette + trackside decoration + feel:
  - jungle: greens, trees; mud shoulders slow harder off-line
  - snow: whites/blues, pines; reduced lateral grip (drifty)
  - desert: sands, cacti; normal grip, dusty
  - volcano: blacks/reds, lava pools; off-track is extra punishing

## Items (from lucky blocks, one held at a time, Space to use)

- 👻 Jump Scare: every other racer gets a fullscreen scare + scrambled steering ~1.5 s
- 👻👻 Double Jump Scare: scares TWO random racers
- 💨 Boost: self speed burst ~1.2 s
- 🛢️ Oil Slick: dropped behind; whoever hits it spins out
- ⚡ Lightning: every other racer shrunk + 50% slow for 3 s
- 🪩 DJ: a random racer gets a disco ball over their head and runs 25% slower for 5 s
- 🚀 Rocket: homes in on a random racer for ~2 s, then spins them out like oil
  (a well-timed shield blocks it at impact)
- 🪄 Steal: swipes the held item from a random racer who has one
- ⚔️ Sword: drawn for 3 s; ramming another kart slices them into a spin
- 🛡️ Shield: 4 s bubble that blocks bullets, turrets, oil, rockets, sword, scares, DJ, lightning

## Garage: colors, car classes & pets

Players pick a character color (12-color palette) and a car, persisted on the
Piezas player record (`color`, `car`) and shown to everyone on track:

- 🏎️ Blaze: +8% top speed  ·  🚜 Boulder: recovers from hits 40% faster
- 🏁 Drift King: sharper steering, grips on ice  ·  🐞 Lucky Bug: starts every race holding an item

Pets are one-time purchases (own forever, equip one) that ride along beside the
kart; abilities stack multiplicatively with the car's:

- 🐶 Zoomie the Pup (500 ⭐): +5% top speed and acceleration
- 🐢 Tank the Turtle (500 ⭐): "stronger" — recovers 35% faster from oil,
  road blocks, bullets and every other knock
- 🐱 Magnet Cat (350 ⭐): grabs lucky blocks from ~26 px farther away

Owned pets live in `pets` (JSON array) with the equipped one in `activePet`;
buying the first pet auto-equips it. `POST /api/shop/pet` buys,
`POST /api/profile { activePet }` equips/unequips.

## AI robot racers

The host adds 0–20 robots in the waiting room (`set_bots { count, skill }`;
skill = easy / medium / hard / random "surprise mix"). The server appends them
to the roster at start as extra slots (`bot: true`, seeded fun names, random
cars) and the HOST's client simulates them — same victim-authoritative model,
with the host acting as every bot's authority:

- Bots follow the centerline with skill-based cruise speed, corner slowdown,
  lane preference and steering wobble; aggressive bots take pot shots.
- Bots are hit by bullets, road blocks, oil, traps, turrets, rockets, DJ,
  scares, lightning, BOOM and hypnosis; the host reports their hits
  (`hit { victimSlot }`) so humans still earn +5 hit bonuses off them.
- Bot states fan out as one batched `bot_states`/`peer_bot_states` message per
  tick; `bot_fire` and `bot_finish` are host-only and cost no ammo.
- Bots count toward the placement field, so beating a pack of robots earns real
  points (and a W) even in an otherwise solo race. Bots never earn points or
  touch player records; unfinished bots place after humans, never as leavers.
- If the host quits mid-race the bots freeze — documented trade-off of
  host-side simulation.

## Big-ticket abilities (shop consumables, server-enforced)

- 🗼 Turret (300 ⭐, T): placed on track; auto-aims and shoots non-owner karts
  within range for 30 s (victim-authoritative like all combat)
- 💥 BOOM (400 ⭐, X): sends every other racer back to the start line. Only ONE
  boom can be used per race — first come, first served (server-enforced)
- 🌀 Hypnotize (2000 ⭐, H): every other kart mirrors the user's driving for 6 s.
  Once per race per player (server-enforced)

All SFX generated with WebAudio (no binary assets). Jump scare is cartoon-spooky,
not gore.

## Camera

Mario Kart-style chase camera: pseudo-3D ("mode 7") perspective ground rendered
from a pre-baked world texture, sprites projected by depth, biome sky on the
horizon. The simulation itself stays 2D top-down; only the view is 3D-ish.

## Combat & Economy

- **F fires a bullet** (spins the opponent on hit); **B drops a road block**
  behind you (heavy crash on contact; blocks shatter after one hit).
- Ammo comes from a persistent per-player wallet stored on the Piezas `player`
  record: `points`, `bullets`, `blocks`, `armorBullets`, `armorBlocks`.
  New players start with 30 bullets + 10 blocks. Hard cap: 100 blocks owned.
- The server enforces ammo during races (relayed `fire`/`place_block` are
  counted against the wallet) and banks results at race end.
- Armor: one armor point absorbs one hit of its type (shield flash instead of
  a spin-out). Victim's client reports hits/absorbs; server debits armor and
  credits the shooter's hit bonus.
- **Points formula** (server-side, by placement): 1st = 80 + 20×level, last =
  20 + 5×level, places between on a linear scale; leavers get 0; solo practice
  races earn 0; +5 per landed hit, capped at +50 per race.
- **Shop** (lobby, `POST /api/shop/buy`): bullet 5 ⭐, road block 8 ⭐,
  bullet/block armor 15 ⭐ each.

## Controls

Keyboard: arrows/WASD to drive (↑ accelerate, ↓ brake/reverse, ←/→ steer),
Space uses the held item, F fires, B drops a road block, T places a turret,
X triggers BOOM, H hypnotizes.

Touch (iPad/phone): drag the on-screen pad — up = gas, down = brake, sideways
= steer — plus tap buttons for item/fire/block/turret/boom/hypno. Throttle and
steering are analog end-to-end.

## Non-Goals (v1)

- Server-authoritative physics / anti-cheat
- More than 10 human players per race (robots go to 20 on top)
- Persistent friends/parties, chat
- Piezas integrations (no third-party providers needed)
